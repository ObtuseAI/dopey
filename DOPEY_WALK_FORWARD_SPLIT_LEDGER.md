# DOPEY WALK-FORWARD SPLIT LEDGER

This ledger enumerates the canonical splits built by the stronger walk-forward consistency
expansion (`dopey_walk_forward.consistency_runner`). All splits are deterministic, offline,
fixture-based, and live-blocked.

The canonical plan `dopey-stronger-wf-plan-dopey-stronger-wf-v1` contains 8+ splits across
rolling / blocked / anchored / regime_holdout / stress_holdout split types. The ledger
below is generated dynamically; the list below is the deterministic output of the
`build_stronger_walk_forward_splits` builder over the 24-window corpus.

## Split types

| Split type | Min count | Description |
| --- | --- | --- |
| `rolling` | 3 | each split = 2 prior windows for train + 1 for validation + 1 for holdout; ordered, leak-free |
| `blocked` | 2 | each split = disjoint 3/3/3 train/val/holdout blocks; no leakage by construction |
| `anchored` | 1 | train = first 2/3, val = next 1/6, holdout = final 1/6 |
| `regime_holdout` | 1 | holdout = `macro_shock_risk_off` windows; train/val = rest |
| `stress_holdout` | 1 | holdout = `high_spread_bad_fill` + `low_liquidity_decay` + `macro_shock_risk_off` + `macro_contradiction_pressure` + `surface_instability_fakeout` + `short_duration_bad_fill` + `vol_expansion_trap` + `compression_shock_failure` |

## Intended test coverage

| Coverage | Description |
| --- | --- |
| regime coverage | every required regime tag in `REQUIRED_REGIME_TAGS` is represented in at least one train/val/holdout window across the splits |
| stress coverage | the stress-holdout split covers at least one of the bad-fill / macro-shock / contradiction / surface-instability / short-duration / vol-trap / compression-shock regimes |
| regime holdout coverage | the regime-holdout split contains at least one `macro_shock_risk_off` window in its holdout |
| family coverage | every strategy family (`directional_convexity`, `volatility_expansion`, `volatility_compression`, `short_duration_defined_risk`) is targeted by both the rolling plan and the blocked plan |
| cross-family coverage | the rolling + blocked + anchored + regime + stress splits exercise multiple families simultaneously so cross-family consistency verdicts can be computed |
| persistence coverage | each strategy is replayed across at least 5 splits (3 rolling + 2 blocked + anchored + regime + stress) to test improvement persistence |
| holdout coverage | every split's holdout windows are stress-tested; the holdout robustness score aggregates across all splits |

## Per-split fields

| Field | Description |
| --- | --- |
| `split_id` | deterministic id derived from a SHA-1 of sorted window ids (so re-runs are stable) |
| `train_windows` | tuple of walk-forward window ids used for train |
| `validation_windows` | tuple of walk-forward window ids used for validation |
| `holdout_windows` | tuple of walk-forward window ids used for holdout |
| `regime_tags` | sorted tuple of distinct regime tags covered by the split |
| `split_type` | one of `rolling`, `blocked`, `anchored`, `regime_holdout`, `stress_holdout` |
| `notes` | human-readable note (seed + index) |

## Reproducibility

The split ids are derived from a stable SHA-1 of the sorted window id lists, so the same
input windows always produce the same `split_id`. To re-generate this ledger, run:

```python
from dopey_walk_forward.split_builder import build_stronger_walk_forward_splits
from dopey_walk_forward.window_model import load_walk_forward_windows

splits = build_stronger_walk_forward_splits(load_walk_forward_windows())
for s in splits:
    print(s.split_id, s.split_type, s.regime_tags, len(s.train_windows), len(s.validation_windows), len(s.holdout_windows))
```

## Holdout window set

The runner also writes a `HoldoutWindowSet` covering windows used by the regime-holdout and
stress-holdout splits. The set is used by `FamilyConsistencyProfile` and by
`HoldoutRobustnessScore`.

## Notes

- The 24-window corpus is loaded from `dopey_data/fixtures/walk_forward/`. The 12 new
  windows (`window_013_train` … `window_024_holdout`) were generated by
  `dopey_data/fixtures/walk_forward/build_stronger_corpus.py`.
- All splits are built from the 24-window corpus, never from real market data.
- The `deterministic_seed` field on each plan is propagated into ProofLedger and
  audit records so the audit can verify reproducibility.
